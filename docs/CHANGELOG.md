# Changelog

Newest first, one section per day (`## YYYY-MM-DD`), and within a day one line per
user-visible change grouped Added / Changed / Removed / Fixed in that order. Write
the line under today's date as part of the change, creating the heading if today
has none yet ([0024](decisions/0024-changelog-is-dated-by-day.md)).

## 2026-07-27

### Added

- Claude Code statusline card — three profiles for the bar under the prompt, each one `/statusline …` line you send as a prompt; Claude Code writes the script and patches `settings.json` itself, so one line covers every OS and there's nothing hosted to maintain. The recommended profile is the two-line bar the team already runs (repo and branch, model, effort, context used, 5-hour and weekly limits with resets, cost, lines changed, session duration — minus the separate context-window size, which `model.display_name` already carries, so printing both reads "Opus 5 (1M context) 1M"), plus a `fast` flag when fast mode is on, since that silently doubles the per-token price and nothing else on screen says so. The second is a single line that keeps where you are and what you've changed but loses the whole usage/cost/clock line; the third is model, effort and context only, and draws without a git lookup. Each one shows a sample of the bar it produces underneath it, because a profile you can't see is one you can't choose between — `ModalStep` gained an optional `preview` for that. The card also states the two things no profile can show: permission mode (that line is Claude Code's own footer, drawn below the statusline and not replaced by it) and rate limits before the session's first API response, which are also blank outright on API billing. It sits in Project Setup rather than AI Tools, since a statusline is a preference and not a tool: no checkbox, no progress denominator, and nothing for the detect scan to look for ([0028](decisions/0028-statusline-card-via-slash-command.md)).
- uv card — Astral's Python tool manager, which fetches its own interpreter, so a Python-based CLI can be installed without a system Python. Back after [0019](decisions/0019-graphify-removed.md) removed it as Graphify's orphaned prerequisite, this time described on its own terms rather than as one tool's dependency.

### Changed

- The tools page fills the screen instead of a 1152px column, and the cards flow into as many columns as fit — three on a laptop, five at 1920, seven at 2560, where before it was always three. A category rail appears from 1280 up with per-category installed counts and scroll-spy, so a 46-tool page is navigable without scrolling; below that the same categories ride in the sticky bar as a swipeable strip of chips you can tap to jump. The search row is now that sticky bar, with a `/` shortcut, and section headers stick beneath it while you read a long section. The progress count follows you down: once the header's bar scrolls out of view it unrolls into the rail, and below 1280 the sticky bar's own bottom edge becomes a 2px accent line filling to your percentage — one indicator at a time, never two, never missing. Cards lift on hover and show their installed state on the card itself (accent border, filled check) rather than only in the checkmark's colour. Tools your OS can't run stopped renting a full greyed-out card each and collapse into one "Not on Windows (x64):" strip at the end of their section ([0020](decisions/0020-fluid-layout-and-category-rail.md)).
- Full AI setup is now walk-away shaped: a STEP 0 block asks for every personal value in one message — pointing at the step that produces one when you don't have it to hand, rather than just repeating the question — and kicks off the long downloads (Xcode from the App Store, `brew fetch --cask android-studio`) before anything installs, the `[HUMAN]` GUI steps collect into one block at the end instead of stopping the run one at a time, and the elevation-needing installs run as one contiguous burst right after the questions so UAC and `sudo` get their clicks while you're still at the machine. The modal's start command carries `--dangerously-skip-permissions` with a note on what that means and on the OS prompts no permission mode can absorb, and the prompt itself opens with the same disclosure — it's downloadable and built to be pasted around a team, so the warning has to travel with it rather than staying on the page that generated it. The Android SDK, the Pixel AVD and Xcode's first-launch and simulator-runtime steps are no longer offered to the agent as an optional CLI shortcut — they are its job, via `sdkmanager`/`avdmanager`/`xcodebuild`, with the GUI wording as a stated fallback only if the CLI fails ([0023](decisions/0023-ai-setup-front-loads-asks-not-subagents.md)).
- The AI setup modal now says what the run will be like before you start it: total time, how much of it you can be away for, and a four-line timeline — questions up front, the admin-prompt block to stay for, the hands-off stretch, the steps only you can do at the end. Every number is counted from your own selection as you tick tools on and off (4 questions and 7 hands-on steps on Windows with everything selected, 4 and 8 on macOS), so it can't drift from what the prompt actually contains. Durations are deliberately coarse and scale off the counts — a per-tool duration table is a thing nobody would keep accurate ([0023](decisions/0023-ai-setup-front-loads-asks-not-subagents.md)).
- Docker Desktop, Reactotron (Windows) and Zoho Cliq desktop gained install commands — `Docker.DockerDesktop`, `InfiniteRed.Reactotron` and `Zoho.Cliq` on winget, `docker-desktop` and `zoho-cliq` casks on macOS. All three were download-only links, which meant the AI setup handed them to the user as GUI installs when a one-line install existed the whole time; three of the twelve hands-on steps disappear ([0023](decisions/0023-ai-setup-front-loads-asks-not-subagents.md)).
- This changelog is dated by day, newest first, and the team setup prompt scaffolds the same shape — 41 of its 43 entries had piled into one undated section, so nothing enforced the order it claimed ([0024](decisions/0024-changelog-is-dated-by-day.md)).
- The AI setup and Detect modals are wide (1024px, up from 672px), because their content needed it: the prompt and scan script stopped wrapping mid-sentence at ~78 monospace columns and now get ~123, and the tool list goes to four columns. Prose inside them caps at 32rem — the intro was running ~90 characters a line even at the old width, so the shell got wider and the reading measure got narrower. The tool grid also sized itself off the *viewport*, so on a wide screen it went to three columns while sitting in a 632px panel; it uses container queries now and responds to the panel. The per-tool modals stay 672px ([0025](decisions/0025-modal-width-follows-content.md)).
- The three toolbar buttons now rank themselves. "Full AI setup" is the one control that installs everything at once, so it moved off the shared green onto its own indigo `--ai` token with a light travelling around its edge; "Detect installed" is accent-tinted — highlighted but not shouting; "Collapse all" stays plain. Green now means one thing only: installed, or the action that installs a single tool.

### Fixed

- Restoring a herdr workspace brought back every tab and its folder and not one conversation — each pane a bare shell, each chat to be found again through `/resume`. The card had promised the opposite, that herdr "reopens the workspaces it saved itself": true of tabs and folders, but an agent pane resumes only where an official integration has reported that pane's native session id, and the card never installed one. It ships `herdr integration install claude` now — one line with no platform variant, and the first step on that card to count as machine setup rather than reference, so the AI setup runs it instead of leaving it for the reader to notice. `session.resume_agents_on_restore` already defaults to `true`, so writing it into `config.toml` — the first fix attempted, on a real machine — changed nothing; the integration was the only missing piece, and also the only one needing no per-OS path ([0029](decisions/0029-herdr-persistence-needs-the-integration-not-config.md)).
- The AI setup would have skipped the JDK on a machine already carrying a newer Java. Rule 1 told the agent to skip anything "present and healthy", and JDK 20 answers `java -version` perfectly well, so React Native's hard requirement on 17 went uninstalled and Gradle failed later on the mismatch the card itself warns about — the same version-blind check [0022](decisions/0022-jdk-detected-by-pinned-paths-not-javac.md) fixed in the detect scan, left standing in the other derived surface. A pinned version now means that version: the agent checks it, installs the pinned one regardless of what else is present (parallel JDKs coexist safely), and resolves it without asking. The final verification checks `JAVA_HOME` resolves to the pinned JDK rather than to any JDK, since Gradle reads `JAVA_HOME` and not PATH. Repointing `JAVA_HOME` is the one change with a blast radius beyond this setup, so its old and new values go in the closing summary — a line in a report, not a mid-run question ([0023](decisions/0023-ai-setup-front-loads-asks-not-subagents.md)).
- Clicking the category rail's last row scrolled to the bottom and highlighted MCP Servers instead. Two things were wrong: the click was never recorded at all — the highlight came only from the scroll observer — and the sections at the end of the page can never win that observer's band, which stops at 35% of the viewport height while their headings sit below it at full scroll with no more page to scroll. So scrolling to the bottom by hand was wrong too, with no clicking involved. A clicked row is now held until you scroll for yourself, and the end of the page names the last section directly. The chips strip below `xl` marks the chip you tapped — still no scroll-spy there, which would drag the strip out from under your thumb ([0026](decisions/0026-rail-highlight-follows-clicks-not-only-scroll.md)).
- Detect scan ticked the JDK card green for any Java at all: it checked `javac` on PATH beside its version-pinned paths, and checks are any-of, so JDK 21 with no 17 read as installed — telling you setup was done right before Gradle failed on the mismatch the card itself warns about. It now rests on version-pinned paths only, widened to Zulu/Temurin/Microsoft and the arm64 Linux layout ([0022](decisions/0022-jdk-detected-by-pinned-paths-not-javac.md)).
- Twelve cards showed no version badge — Cursor, Android Studio, Docker Desktop, pgAdmin, Postman, Termius, Zoho Cliq, Slack, the JDK, and the three plugin cards. Cursor's own version endpoint sends no CORS header and it publishes no GitHub releases, so the installer-only apps now read the Homebrew cask API (same cask they install from, `Access-Control-Allow-Origin: *`, no rate limit); the plugin cards had GitHub releases all along. Xcode, Cisco, Teams desktop and the remote MCP servers stay bare on purpose ([0021](decisions/0021-version-badges-via-homebrew-cask-api.md)).
- Version badges can be per-platform, for the two cards where one number can't be right for everyone: Teams ships a different build per OS (mac shows the cask number, Windows/Linux stay bare) and the Homebrew / winget card fronts a different package manager per OS (mac and Linux show Homebrew's) ([0021](decisions/0021-version-badges-via-homebrew-cask-api.md)).

## 2026-07-26

### Added

- herdr card gained a setup modal whose one pasted line writes a double-clickable launcher (Windows `.lnk`, macOS `.command`, Linux `.desktop`) wherever you choose, defaulting to the Desktop, carrying herdr's own icon. The launcher script and icon ship in `public/`, so there's nothing to download ([0010](decisions/0010-hosted-launcher-script-and-image-fields.md)).
- Custom launcher icon by drag-and-drop or file picker, resized and converted to a real `.ico`/`.png` in the browser (Windows/Linux; macOS keeps the Terminal icon). The icon rides inside the pasted line, so it's still one copy-and-paste with nothing to download or save.
- Ponytail card in AI Tools — a Claude Code plugin that holds the agent to the least code that solves the problem; picked over Caveman and Impeccable ([0011](decisions/0011-ponytail-over-caveman-and-impeccable.md)).

### Changed

- The AI setup no longer asks the agent to install what you've already ticked off. Tools checked on the page show a ✓ with their name struck through instead of a checkbox, and the prompt lists them under `ALREADY INSTALLED` — don't install, and if something depends on one and it's actually missing, tell the user rather than quietly installing it. Kept separate from `USER-EXCLUDED`, whose "don't count them as missing" instruction would be wrong here. Untick the card on the page to bring a tool back; there's deliberately no second control in the modal. Claude Code counts too — tick it off and step 1 disappears, leaving one paste instead of two ([0018](decisions/0018-ai-setup-skips-installed-tools.md)).

### Removed

- graphify, entirely — the Graphify and uv cards (uv was only there as its prerequisite), their detect specs and icons, the committed graph, the `## graphify` block and prerequisite line in CLAUDE.md, the two `PreToolUse` hooks that injected "MANDATORY: run graphify query" into every Bash/Grep/Read/Glob, `.gitattributes` (a merge driver for the graph), and the `graphify-out/` ignore rule. It cost a dirty tree after every push — the rebuild hook is post-commit, so it can never include its own output — plus ~11,000 lines of churn per commit, a `manifest.json` of per-file mtimes that dirties on every machine regardless of code, and a scoped rebuild that quietly returned fewer nodes and edges than a full one. For a 32-file, 4,000-line codebase where a full grep takes 30ms, the graph was an order of magnitude larger than the code it described. A replacement will be picked separately ([0019](decisions/0019-graphify-removed.md), supersedes [0015](decisions/0015-ship-the-knowledge-graph-in-the-repo.md)).
- Each section's "Copy all" button — unused, and wrong five ways: it dropped secondary commands, silently omitted any card whose action is a download, ignored `inScript`, labelled nothing, and never touched modal steps (which need per-user field values a bulk copy can't supply). The per-card copy button and the AI Setup modal already cover both real jobs. The "setup script" derived surface goes with it, so the ripple checklist in CLAUDE.md and README no longer charges maintenance for it ([0017](decisions/0017-copy-all-removed.md)).
- `Category.inScript` — dead since it was written. Only the per-tool `t.inScript` is ever read, so `mcp`'s `inScript: false` did nothing and read as working. Deleted rather than wired up: MCP servers belong in the AI setup, `claude mcp add` being a command the agent can run ([0016](decisions/0016-category-inscript-deleted-not-wired-up.md)).

### Fixed

- Detect scan reported a freshly installed Claude Code plugin as missing: it searched `~/.claude.json`, which only records a plugin once it has been used, rather than `~/.claude/settings.json`, which records it at install. Superpowers, UI/UX Pro Max and Slack passed only on usage history; installing Ponytail and scanning is what exposed it ([0012](decisions/0012-plugins-detected-via-claude-settings-json.md)).
- Typed modal values reached the shell unescaped — double-quoted for git identity, the SSH key comment and the Zoho MCP URL (where `"`, `$` and a backtick are all still live), and bare for the fnm/pnpm/yarn version fields. All seven moved to single-quoted literals behind the same `shellQuoted` escape the herdr launcher uses, so a name like O'Brien fills correctly instead of splitting the command.
- The `--dangerously-skip-permissions` callout in the AI setup modal was 512px wide inside a ~970px dialog, so the page's one safety warning was also its narrowest box. `max-w-lg` was capping the bordered container instead of the prose inside it; the box now fills the modal like its neighbours and the text keeps its readable line length, the same shape the "Included tools" panel twelve lines below already used.
- "View setup" was styled solid accent on cards that had no install command and outlined on cards that did, so the emptiest cards (Superpowers, Ponytail, the plugin-style MCP servers) shouted loudest while a card full of commands whispered. It's always the quiet outlined button now; the solid accent is reserved for the action that actually installs the tool.
- Tool modals listed the prerequisite below the fill-in fields, so you only learned what you needed after filling the form in — it now sits directly under the intro, above the fields.
- herdr launcher dropped its "Start folder" field: `herdr` takes no path argument and restores its own saved workspaces, so the field set a working directory that only ever affected a first-ever launch while reading as though it chose the project.
- herdr launcher didn't check the install folder — a typo silently created a directory tree and hid the launcher in it — and `~`, which the placeholder suggests, was expanded on Unix but not on Windows. It now expands `~` everywhere and refuses with the offending path named.
- The launcher's failure paths called `exit`, which closed the whole terminal — it runs inside the user's session via `&([scriptblock]::Create(…))`, not a child process — so the message vanished with the window. They `return` now.
- A failed icon fetch deleted the installed icon before validating the replacement, leaving a working launcher iconless; the download is checked aside and only swapped in once it passes.
- The herdr launcher aborted before writing anything under PowerShell 7: its icon check read magic bytes with `Get-Content -Encoding Byte`, a 5.1-only switch that throws in 7, and `$ErrorActionPreference = 'Stop'` turned that into a dead stop on the default no-custom-icon path. It reads via `[IO.File]::ReadAllBytes` now, which both editions accept.
- Smaller launcher and modal fixes: the icon one-liners deleted the temp icon they wrote; `--dest`/`--icon-file`/`--icon-url` now name the option when handed no value instead of failing on a bare `shift`; the icon drop zone stopped flickering its border when the cursor crossed the preview mid-drag.
- `pnpm build` never typechecked the relay: `functions/` was in no tsconfig, so a type error there deployed unnoticed. `tsconfig.node.json` now includes it (verified by injecting an error and watching the build fail). `scripts/` stays out — it runs under `tsx`, and bending a working dev script to `nodenext` resolution rules buys nothing.

## 2026-07-25

### Changed

- Detect scan now also finds MCP servers and Claude Code plugins (via `~/.claude.json`) — only per-project steps remain unscannable; the modal was simplified to a one-line coverage summary instead of the per-tool checkbox panel ([0007](decisions/0007-simple-detect-modal-and-config-detection.md)).
- Detect scan now applies its whole result at once — it ticks what it found and clears what it didn't, instead of ticking only and leaving an "Uncheck these N on the page too" button to finish the job. A single Undo in the result panel puts the checklist back exactly as it was, which is what protects a tick the scan can't see ([0013](decisions/0013-detect-applies-whole-result-with-undo.md)).
- React Native Setup and Project Setup no longer carry checkmarks — they're actions you repeat in every repo, not machine state, so a permanent tick against them meant nothing. Both moved to the end of the page and dropped out of the progress count, which now reads 42 tools rather than 47 ([0014](decisions/0014-per-project-sections-are-not-checkable.md)).
- fastlane moved from React Native Setup to System Essentials — it's a `brew install` CLI like Watchman and CocoaPods, not a per-project step, and it keeps its checkmark, version badge and detect check where it now sits.
- All project docs consolidated under `docs/` (changelog, todo moved; README/CLAUDE.md stay at root) ([0008](decisions/0008-all-docs-live-in-docs-folder.md)); tool changes now carry a written ripple rule in CLAUDE.md and README ([0009](decisions/0009-tool-changes-ripple-everywhere.md)).
- Multiline command/prompt blocks gained a download button (scan script saves as `scan.ps1`/`scan.sh`, prompts as `<card-id>-prompt.md`); manual do-it-yourself steps in tool modals render as instructions instead of copyable command boxes.
- Team plugin prompt: the package-manager hook now derives the right manager from the host repo (`packageManager` field / lockfile) instead of enforcing one team-wide answer.
- Team setup prompt: scaffolds the docs system and may propose up to two repo-specific skills/agents (confirmation-gated) after studying the codebase.

### Fixed

- The Windows detect scan never reported back: its report step was the script's one multi-line block, and pasting into PowerShell parks an unclosed brace at the `>>` prompt, so the whole `Invoke-RestMethod` sat there unexecuted while every single-line check above it ran. It's one line now, and both scripts end with a newline so the last line actually submits.
- Copy/download tooltips on command blocks were clipped by the modal edge — they now grow leftward from the button.
