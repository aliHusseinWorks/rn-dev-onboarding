## 2026-08-13

### Changed

- The Atlassian card installs three token-authenticated servers, one per product, instead of pointing at Atlassian's own Rovo endpoint over OAuth. The 11th's correction stopped the card naming Bitbucket because the consent screen offers Jira, Confluence and Compass and nothing else; this replaces that limitation rather than recording it. Rovo's Bitbucket tools authenticate by API token, so an organisation that has not enabled that route gets none of them, which is not the reader's to change — a scoped token authenticates as the user against plain REST and the gating does not apply. It is also the only route left, app passwords having been removed on 28 July 2026. What it costs is now on the card rather than only in the decision: three community packages by one maintainer in place of one first-party server, holding a token kept in cleartext in `~/.claude.json` with write access to all three products. The card is `inScript: false`, because its three commands are `alt` siblings and the machine-setup prompt drops those — it was emitting no command while still telling an agent to have the user mint that token, which invites a live credential into a session transcript. The detect needle matches `mcp-server-atlassian`, since the card installs one to three servers and a needle on any single name would read red for someone who wanted another. The card is "Atlassian" again, with Bitbucket in its description, a version badge against [0021](decisions/0021-version-badges-via-homebrew-cask-api.md)'s now-false exclusion, and a three-field modal in place of the copy-command button ([0046](decisions/0046-atlassian-authenticates-with-a-scoped-api-token.md)).

- The macOS herdr launcher is a `herdr.app` carrying its own icon, where it was a `herdr.command` that could only ever show the generic Terminal one. Windows and Linux already had icons, so this is macOS catching up rather than a new idea, and the artefact is renamed: anyone who ran the old launcher keeps a working `herdr.command` beside the new bundle, which the script now says out loud rather than deleting a file it did not create this run. Two findings are why it is not simpler. A hand-rolled bundle whose `CFBundleExecutable` is a shell script is refused by Launch Services with `-10669`, each other candidate ruled out separately, because it wants a Mach-O — `osacompile` supplies Apple's own already-signed applet. Replacing `applet.icns` is then still not enough: `osacompile` ships an `Assets.car` holding the same applet icon plus a `CFBundleIconName` pointing at it, and that key outranks `CFBundleIconFile`, so the first build showed the white AppleScript scroll with a correct icns sitting unread beside it. `sips -s format icns` cannot do the conversion alone either, rejecting any non-square source and any square one whose side is not a standard icon size, 37×37 included, so the source is padded to square with `sips -p`, which keeps alpha and matches the letterboxing the page's own resize does, then scaled per size into `iconutil`. All three tools are base macOS, so nothing new is required. The card's custom-icon field now appears on macOS, where the icon-carrying step had listed no mac keys and so filtered itself out ([0045](decisions/0045-the-macos-launcher-is-an-osacompile-applet.md)).

## 2026-08-11

### Changed

- The Zoho card's detect needle keys off `zohomcp.com` rather than the server key `"zoho-cliq"`, and its `docsUrl` is Zoho's own MCP page rather than a Cliq help article. Making the card generic broke its own detection: the command now takes the server name from a field, so a reader who names theirs `zoho-chat`, or who adds Sprints alone, had a card that could never tick green — it worked only for a reader who happened to pick the name the needle was written for. Zoho is the only card that puts a token in the name slot; every other one dictates the name, so its needle matches by construction. The `DetectSpec` comment now says that, since the next card to offer a name field will hit the same wall.

- The Zoho card is "Zoho MCP" and says one server per Zoho app. A single Zoho MCP server can carry several apps, and a real one carrying both loaded **166 tools** — 91 Cliq plus 75 Sprints — into every session. The console has no bulk untick, so pruning a bloated server means clicking ~146 boxes one at a time, which makes tool choice a creation-time decision rather than something to fix later. It takes a name and a URL, so the one `claude mcp add` covers whichever apps a reader's console actually offers — Cliq and Sprints here, Projects or Desk elsewhere — instead of naming two services the card cannot know are the right two. Adding another app means changing both boxes and copying again. The tooltip gives the rule — tick only what you would otherwise do by hand — with Cliq's 13 of 91 and Sprints' 25 of 75 as the worked examples, and draws the line at delete: every Delete and Remove tool stays unticked along with sprint lifecycle, project and release admin, billing approval and channel administration, because a wrong `UpdateItem` is one undo and a wrong `DeleteSprint` is not. A third step records what the earlier card left out — editing the ticked tools later needs a Claude Code restart, since a client reads the tool list when it connects and a running session keeps the old one, while the OAuth grant itself survives.

- The Atlassian card no longer advertises Bitbucket in its name. Its OAuth consent screen offers Jira, Confluence and Compass and nothing else — Bitbucket tools are on that server, but they authenticate by API token, so an organization that has not enabled that route gets no Bitbucket at all on a connection that otherwise looks healthy. Calling the card "Bitbucket + Jira" promised something OAuth cannot deliver, so it is "Jira + Confluence" with the API-token gate stated in the note.

- The Atlassian card points at `https://mcp.atlassian.com/v1/mcp` over Streamable HTTP, not `--transport sse` at `/v1/sse`. Atlassian deprecated the HTTP+SSE endpoint with backward compatibility "until 30 June 2026", a date already past, so the card was handing out a URL on borrowed time. The card is named for Bitbucket and the tools are real — `createPullRequest`, `getPullRequests`, `getPullRequestDetails`, `addPullRequestComment`, `analyzePipelineStepFailure` and the rest are listed in Bitbucket Cloud's own MCP docs — but they are invisible from the old endpoint, which is why a connection can look healthy while exposing Confluence only. The note now says Bitbucket tools additionally want the workspace linked to an Atlassian organization and API-token auth left enabled by an admin, since neither is something the reader can fix from a terminal. `docsUrl` moves off the GitHub repo to Atlassian's own client-setup page, which is what now carries the endpoint.

- `.claude/settings.json` gains `"ask": ["Edit(/docs/decisions/**)"]`, and `CLAUDE.md` stops overstating what it does. The contract said editing an existing decision asks first; no `ask` array existed, which is why two decision files were edited in one session with nothing objecting and a review caught it rather than the guard. The rule closes the obvious path only — a scripted write through Bash goes around any `Edit(...)` rule, which is how both of those edits actually happened — so the sentence now says so and points at [0019](decisions/0019-graphify-removed.md), whose "mark the status line, leave the reasoning" rule is the thing genuinely holding that line.

- The verify skill routes between the servers that overlap it, and separates a JS change from a native one. Argent builds, launches, drives and reads logs, so another server's build, screenshot or UI-dump tools and raw `adb logcat` are named as paths that work while losing the JS-layer detail and network payloads Argent is there for; unit tests are the one job outside its scope, pointed at the repo's own test command. No MCP server is named in it — the skill is committed to a repo that may have Windows developers on it, and naming a macOS-only server would leave half the team a dangling reference, the same bug `docs/TODO.md` records against the SSH key card's `note`. The JS-versus-native split is the larger win: Metro serves a JS change, so no build is needed at all, provided what is installed is the debug build Metro is serving — against a release install the bundle is embedded, a reload is a no-op, and the verdict would describe the old code, so the skill makes the agent check and say which it did ([0044](decisions/0044-android-dev-mcp-is-removed-argent-supersedes-it.md)).

- MCP scope follows what the server is about, rather than all eleven cards taking `--scope user`. The XcodeBuildMCP, Android Dev MCP, Sentry and Firebase (Crashlytics) cards are about one repo — the first two only apply inside a mobile project, the other two point at one app's crash data — so they now register with `--scope project` into a committed `.mcp.json`, the same argument Argent's `--local` makes. At user scope they were loading into every session in every project: this repo is a web app, and the two mobile servers were putting 53 tools of iOS and Android tooling into it that nothing here will ever call. The Context7, Atlassian, Slack, Zoho Cliq, Teams and Postman cards stay at `user`, being about you rather than about a repo, and Figma stays too because it scopes to a design file with no reliable mapping to a repo. Two changes come with it, neither optional, because the flag alone would have been worse than the bug [0036](decisions/0036-mcp-servers-register-at-user-scope.md) fixed: the four leave the machine-setup prompt via `inScript: false`, since that prompt runs before any repo is cloned and `--scope project` from the agent's scratch directory would write a `.mcp.json` there — 0036's failure in a different file — and they lose their `DETECT_SPECS` entries, since the scan matches a needle in `~/.claude.json` and a project-scoped server lives in the repo's `.mcp.json`, so leaving the needle would have moved them from wrongly green to permanently red ([0043](decisions/0043-mcp-scope-follows-the-servers-subject.md)).

### Removed

- The Android Dev MCP card. It overlapped the Argent card on everything a developer reaches for — booting an emulator, installing and launching, tapping, screenshots, UI dumps, logs — and two servers answering the same request is the routing failure `docs/argent-guide.md` already records against raw `adb logcat`. A real session pushed the question: tapping through a login flow was slow enough to notice, and the mechanism rather than the machine explains it, since an `adb` wrapper pays a fresh process per action (~100-200ms) and a `uiautomator` dump per screen read (1-5s), where Argent's own claim is that it talks to the device directly and takes multi-step sequences in one call. That claim is still unmeasured here — the card has never been run against a real repo, which `docs/TODO.md` records. The last argument for keeping it rested on an error of ours: this repo had recorded that Argent supports no physical devices, when its README lists "Emulators (AVDs) and physical devices over adb" and only physical *iOS* devices are unsupported, so physical Android was never Android Dev's alone. What is genuinely lost is Metro's lifecycle, which this workflow leaves to the developer's own terminal on purpose, plus ANR traces and `bugreport` — `adb` covers the last two ([0044](decisions/0044-android-dev-mcp-is-removed-argent-supersedes-it.md)).

## 2026-08-10

### Added

- The "Argent" card in Project Setup — `npx @swmansion/argent@latest init --local`, read the diff, restart, then one prompt that sets the repo up for good. It picks up where `react-native doctor` stops, that being a check on the toolchain rather than on whether the app behaves: Argent drives iOS Simulators and Android Emulators, reads device logs and network traffic at both the JS `fetch` layer and the native layer, and can attach a debugger. The prompt reads the repo's schemes, flavors and bundle IDs, asks the four things a repo cannot know in one batch, then writes `docs/dev-setup.md` (committed repo facts), `docs/dev-setup.local.md` (gitignored devices and test account, ignored before it is written so an interrupted run cannot strand the password in the tree), the two `CLAUDE.md` `@` imports that actually expand them, and `.claude/skills/verify/SKILL.md` — after which the card is never opened again, because the skill loads itself whenever a task matches. `--local` over global mode and Project Setup over MCP Servers, both for reasons that first pointed the other way; the missing `DETECT_SPECS` entry is the `checkable: false` category working as intended. The skill encodes only observed failure modes, chief among them that Argent declares victory early: given a vague goal it fixes something, sees a plausible screen and reports success. So a pass condition is stated before anything is touched, a device name that does not exist here stops the run rather than being substituted, and build commands come from `android/app/build.gradle` and `xcodebuild -list` every run rather than a document — removing staleness as a category instead of managing it ([0041](decisions/0041-argent-is-a-repo-scoped-card-not-an-mcp-one.md)).

### Fixed

- Tooltips no longer get cut off inside a tool modal. `Tooltip` portals its panel to the body, positions it `fixed`, measures it on hover and clamps it to the viewport on both axes, flipping sides when the preferred one has no room. The `align` prop goes with it — seven callers were hand-steering `align="end"` to dodge the clipping — and so does the comment in `App.tsx` conceding that a step carrying a tooltip "needs a short note", which was the constraint this imposed on every future card. Worth knowing why the obvious half-fix is wrong: `position: fixed` escapes `Modal`'s `overflow` clipping and silently breaks every tooltip outside a modal, because `CategorySection`'s sticky header carries `backdrop-blur` and `backdrop-filter` establishes a containing block for fixed descendants — the section tooltips computed a correct `top: 328px` and rendered at `y: 612`, offset by wherever that blurred ancestor sat. Leaving the tree removes both problems at once: no ancestor can clip a body child or become its containing block. Verified over CDP rather than by eye, since the broken intermediate looked fine: 42 triggers hovered with real mouse input across three viewports in three states each — page, modal, and modal scrolled — of which 40 opened a tooltip, all on screen, none left open afterwards. That the panel re-measures when its label changes width was proved by breaking it on purpose and watching the left edge stop moving ([0042](decisions/0042-floating-layers-portal-to-the-body.md)).

## 2026-08-07

### Added

- A `Tool` carries `elevated`, and the AI setup gathers every elevated tool into one block in STEP 0 for the user to run in a real terminal before walking away. The prompt used to tell the agent to group these itself and prime `sudo -v`, which cannot work — its shell has no tty, so `sudo` fails rather than prompts, and the `! <command>` fallback rule 6b offered fails the same way. On macOS the flag marks the `pkg` casks plus the Homebrew installer, which also waits on a RETURN and so stranded an unattended run on the very first card. Rule 6 now names `sudo -v` as something that will not help and says to hand over a command and wait; rule 6b separates browser-login handshakes, which do work through `!`, from anything needing typed text, which does not. The flag is per-platform, taking the same bare-or-map shape as `version` with `resolveElevated` beside `resolveVersion`, and the Windows values are read off the winget manifests rather than guessed: `Docker.DockerDesktop` and `Microsoft.OpenJDK.17` are `Scope: machine` with `ElevationRequirement: elevatesSelf`, while `Microsoft.Teams` is a user MSIX and `Zoho.Cliq` is `Scope: user`, so neither belongs in the block — elevating them would have been worse than pointless, since a user-scope MSIX installed from an elevated PowerShell registers against the administrator account. Windows gets three items, macOS five, and Linux needs no flags because a command that literally begins with `sudo` is collected on sight, which is what catches `sudo apt-get install -y git` on a card whose macOS command needs no password at all ([0038](decisions/0038-elevated-installs-are-one-block-the-user-runs.md)).
- A `Tool` carries `sizeMb`, and the modal names the download total for the current selection — "this selection pulls ~18 GB — on slow Wi-Fi it is hours, not minutes". The estimate is still `count × 0.7` minutes, which was promising 30 minutes for a run that took four hours because it counts tools and this list is bytes. Sizes are measured rather than estimated — `Content-Length` on the real download, or the dmg/pkg Homebrew leaves in its cache — and summed over the selection rather than hardcoded, so unticking Xcode reads ~6 GB and so does Windows. Formula-installed tools carry none, deliberately: a bottle's cost is mostly its dependency tree, which is not the card's to name. Xcode's figure includes the iOS simulator runtime and Android Studio's the SDK packages, neither of which has a card to hang a size on ([0039](decisions/0039-the-estimate-names-its-download-total.md)).

### Changed

- Every `claude mcp add` carries `--scope user`. Nothing prompts for scope — the flag defaults to `local`, in `add`, `add-json` and `add-from-claude-desktop` alike, and there is no interactive add path — so a reader pasting a card into whatever terminal was open silently got a server confined to that folder. A real run registered all seven into a scratch directory, invisible from the repo they were for. The detect scan was ticking those green, because a folder-scoped server still writes the needle it looks for ([0036](decisions/0036-mcp-servers-register-at-user-scope.md)).
- The Node card symlinks `node`/`npm`/`npx` from fnm's `default` alias into `~/.local/bin`, and no longer chains with `&&`. fnm publishes Node only into a per-shell directory that dies with the shell, and only from `~/.zshrc`, which non-interactive shells never read — so the three `npx` MCP servers connected when added and then failed with `ENOENT: npx`. Claude Code's captured environment contained no reference to fnm at all. The old `&&` chain ended in the profile edit, so a failed download left `node` working in one terminal and nowhere else ([0037](decisions/0037-node-needs-a-path-outside-fnms-per-shell-dir.md)).
- Rule 4 splits into 4a for Android and 4b for Xcode, both correcting commands that fail as written. `sdkmanager` needs `--sdk_root="$ANDROID_HOME"` on every call or the standalone command-line tools install packages where nothing looks for them; the AVD also needs a system image and the `emulator` package, neither of which was listed; and `avdmanager` has to be the copy inside the SDK root or it reports `Package path is not valid. Valid system image paths are: null`. `xcodebuild -runFirstLaunch` was prefixed with `sudo` and needs none, while `sudo xcode-select -s` genuinely does and was missing entirely — without it the toolchain stays on the Command Line Tools and iOS builds fail.
- Rule 2c tells the agent a failed download is the expected case: `curl (18)`, `(28)`, `(56)`, an archive that won't unpack. One run lost fnm twice, herdr, Cursor, the Android command-line tools and Android Studio to transient failures, every one of which succeeded on retry. STEP 0's overlap advice is qualified for the same reason — several multi-gigabyte transfers on a thin link stall each other past the server's idle timeout, which is why big downloads were dying while small ones succeeded — and `HOMEBREW_NO_AUTO_UPDATE=1` now guards the prefetch, since an auto-update mid-run bumped the Android Studio cask and orphaned the dmg that had just been fetched.
- The new rules name the right shell, terminal, install prefix and environment-variable syntax for each of the three platforms, rather than treating "not Windows" as "macOS". Written the two-way way first, which handed Linux `zsh -i -l -c`, `/Applications/<Name>.app` and an instruction to open Terminal.app; the Android rule also handed PowerShell the Unix spelling of `$ANDROID_HOME`, which expands to nothing there, so `--sdk_root=""` would have sent every SDK package somewhere no tool looks. The elevated block is per-platform for the same reason. Windows is told to run it in an Administrator PowerShell, because Chocolatey writes to `C:\ProgramData` and fails outright from a normal shell rather than raising a UAC dialog to accept — and elevating is only safe because nothing left in that block writes a user-scope setting, which is exactly why the JDK's `JAVA_HOME` step sits outside it. The block also drops the claim that nothing else can install until it has run, which is true of Homebrew and not of the Chocolatey the Windows card installs as an extra.
- The Node card covers Windows: fnm keeps a stable `%APPDATA%\fnm\aliases\default` that it repoints on `fnm default`, appended to the user PATH. No symlink and no `bin` subdirectory there — `node.exe` sits at the root of a Windows Node install, so the alias directory itself is the thing that goes on PATH.
- Rule 1 checks an install directory for GUI apps, which answer neither a version flag nor `command -v`, and does it before consulting the package manager, which an app installed by hand is invisible to. Rule 8 verifies in an interactive login shell, because `zsh -l -c` does not source `~/.zshrc` and reported a working toolchain as entirely missing. Rule 9 lets a human step be marked BLOCKED when it needs a tenant admin or an IT-supplied value, instead of being re-presented as though another attempt would help.
- `ModalStep.userRun` marks a command only the user can run, splitting a meaning `manual` had been carrying twice. The prompt reads it as "the agent cannot do this" and the modal as "this is not a shell command", which was fine while every `manual` step was GUI wording — `sudo xcode-select -s` was the first that wasn't, and it rendered as prose nobody could copy. `userRun` is `[HUMAN]` in the prompt and counted in `handsOn` exactly like `manual`, and needs no renderer change because it simply isn't `manual`.
- The JDK card is named "JDK 17" rather than "JDK 17 (Azul Zulu)". It installs Zulu on macOS, Microsoft's build on Windows and the distro's OpenJDK on Linux, so one vendor's name was wrong on two of the three, and the badge now carries only the macOS source — the other two have no number worth trusting ([0021](decisions/0021-version-badges-via-homebrew-cask-api.md)).
- `detectScript.ts` escapes `DETECT_SPECS` values before they reach a single-quoted literal — `'\''` for sh, `''` for PowerShell, the two idioms `tokens.tsx` already applies to modal commands. Still true that no spec value contains a `'`; the quoting of a script users paste into their own shell no longer rests on that.
- herdr's detect spec is the hook its integration step writes (`~/.claude/hooks/herdr-agent-state.sh`) rather than `bins: ['herdr']`. Checks are any-of, so the binary alongside it would still have ticked a machine that restores every pane as a bare shell — the thing the integration exists to prevent ([0029](decisions/0029-herdr-persistence-needs-the-integration-not-config.md)).

### Fixed

- The macOS/Linux scan script is handed to `sh` through a quoted heredoc instead of being pasted line by line, which is what made it fail on macOS while Windows was fine. It is an `sh` script pasted into an interactive shell, and macOS ships zsh: there `!` is history expansion, so `#!/bin/sh` alone fails with `zsh: event not found: /bin/sh`, and `#` is not a comment unless `interactive_comments` is set, so every comment line adds `zsh: command not found: #`. A real paste produced **34 errors** and then half-worked — fixing only the reported shebang would have left 33. A quoted delimiter makes the whole body literal, so the per-check comments the script exists to be read for survive with nothing escaped, and the same text still works as a downloaded file via `sh scan.sh`. Verified 0 errors under zsh, bash and dash, and confirmed on a real terminal. The PowerShell script is untouched: `#` comments there, and it has no history expansion ([0040](decisions/0040-the-unix-scan-script-is-piped-to-sh.md)).
- Every value interpolated into either scan script passes through `flatten` before quoting. Single quotes contain `'`, `$` and backticks but not a line break, and the heredoc is what made a break dangerous: a value carrying a line equal to the delimiter closes the heredoc early and hands the rest of the script to the user's *interactive* shell instead of the child `sh`, after a plausible-looking scan has already printed. Unreachable with repo-authored values, but the invariant was unenforced and `security-reviewer` proved it with a working PoC. It also covers the two comment lines, which are interpolated outside any quoting in both generators, where a newline escapes `#` on either shell.
- `sudo xcodebuild -runFirstLaunch` keeps its `sudo` and is the user's step, not the agent's. It was briefly stripped on the strength of a test that proved nothing: `-runFirstLaunch` exits 0 doing no work when the components are already installed, which they were, and they install into root-owned `/Library/Developer`. Rule 4b now says to check `xcodebuild -checkFirstLaunchStatus` rather than reading a silent success as one, and pairs it with `sudo xcode-select -s` as the two Xcode steps that need a password. `xcodebuild -downloadPlatform iOS` genuinely needs none and stays the agent's.
- The generated scan script quotes every `DETECT_SPECS` value it passes rather than only the ones that were already quoted. `bins` and tool ids were interpolated bare into POSIX sh — a strictly weaker position than the sites that got escaped first, since bare interpolation makes a space, `;` or `$(…)` significant — and the PowerShell `Ok`/`No` calls skipped the escaper their neighbours used. Unix path tests moved from a double-quoted literal to a single-quoted one with `~/` spliced in outside the quotes, which is possible because `DetectSpec` gives mac/linux paths no licence to interpolate. The Windows `Test-Path` stays interpretive by design, so `detect.ts`'s note about `$env:` tokens is now load-bearing.
- `shellSingleQuote` from `tokens.tsx` replaces the two local escapers that duplicated it byte for byte; both script builders already take the `platform` it keys off. The claim that it couldn't be imported "because that module carries JSX" was wrong — it exports plain functions and already ships in the same bundle.
- A card whose every modal step is keyed to another OS no longer offers "View setup" and opens an empty panel. `hasModalContent(tool, platform)` gates the button, which the new Windows-only JDK step made reachable on macOS and Linux.
- The estimate stops counting the elevated installs as unattended. They install while the user watches, so their minutes moved out of the walk-away phase into the block phase, which now names how many installs it covers and disappears when none are left rather than promising a block that isn't generated. Each phase is gated on having something in it, because `round5` floors at five — otherwise unticking everything but one elevated tool advertised "~5 min · Walk away — 0 tools install themselves".
- Category rail rows and the chip strip below `xl` are disabled and dimmed when the search has filtered their section out, instead of silently jumping nowhere. All three read one expression — `toolsMatching(category, query)`, which `CategorySection` renders from and the other two test the length of — so they cannot drift. A row or chip that was active before the filter also stops reading as active, since nothing scrolls while you type and the highlight would otherwise stay on a section that isn't there. The search field gained `min-w-56`, so the wrapping toolbar drops it onto its own row instead of shrinking it to a few characters on a narrow phone. The SSH card's note names `%USERPROFILE%\.ssh` alongside `~/.ssh` instead of claiming the Unix path everywhere, and the Android Studio card carries the `avdmanager` `devices.xml` caveat as a tooltip.
- The Xcode card does the simulator runtime with `xcodebuild -downloadPlatform iOS` and keeps the Settings → Platforms route as an alternative, adds the `sudo xcode-select -s` step, and says the runtime is ~8.5 GB. The three plugin cards pass a full HTTPS URL instead of the `owner/repo` shorthand, which can resolve to SSH — and the only key this app sets up is for Bitbucket, so the clone failed on publickey. The Teams MCP card carries the real `authenticate` command and the Entra admin-consent prerequisite for `Microsoft Graph Command Line Tools`, replacing "ask Claude to authenticate", which Claude cannot do. The Zoho Cliq MCP card says to use Create MCP server rather than a pre-configured one, which authenticates and then exposes zero tools, and names a minimal tool selection out of the 302 on offer.

## 2026-08-01

### Added

- Tool modals can hold a `kind: 'choice'` field, rendered by a new `SegmentedControl` and gating steps through `whenFieldIs` — so one card can serve two audiences without a tab component and without a second card repeating half of it. It is native radios styled as a segment rather than buttons, which is why arrow keys, tab order and the announced group name need no code. Steps also gained `tooltip` (the caveat only some readers need, behind an info icon, instead of a longer note), `link` (for a step a terminal can't carry out, like an admin console page), and modals gained `requireFields`, which withholds every step — and the mode picker — until the named field is filled: a command built around an unfilled token looks runnable and isn't, prose carrying the same token reads as broken while numbering itself from 1 as though the steps above it didn't exist, and choosing a path is pointless while everything behind it is withheld. Text fields render before choice fields for the same reason: a field the modal is gated on has to be answerable before anything it gates appears. The modal's intro is what explains the card in the meantime ([0034](decisions/0034-modal-modes-are-a-choice-field.md)).

- `.claude/hooks/guard.mjs` rejects, at Stop, the comment tells `code-style.md` names outright — an emoji, a section banner, a `Note:` prefix — in comment lines the working tree added, reading both `git diff HEAD` and the untracked files a diff can't see. It deliberately stops there: the comments that prompted it were well-formed English that merely restated a decision file, and no regex sees that, so the rule file keeps the judgement half and the script says so ([0035](decisions/0035-comment-guard-enforces-only-the-mechanical-half.md)). The team setup prompt generates the same check, with the two traps that surfaced here — anchor the `Note:` pattern or an ordinary sentence containing "note:" trips it, and read untracked files whole or a new file is the one place the check is blind.
- The footer carries an attribution — "© &lt;current year&gt; Ali Hussein", the name linking to the GitHub account this repo lives under — opposite the existing note about where progress is saved. The year is read at load rather than written into the source, so it can't go stale in January. The two sit on one row from `sm` up and stack below it. The row's right padding is written per-side rather than as `px-*`, because `ScrollTop` is fixed over the last 60px of the viewport and the widest breakpoint's shorthand would otherwise reset the clearance.

- `pnpm build` never typechecked the relay: `functions/` was in no tsconfig, so a type error there deployed unnoticed. `tsconfig.node.json` now includes it (verified by injecting an error and watching the build fail). `scripts/` stays out — it runs under `tsx`, and bending a working dev script to `nodenext` resolution rules buys nothing.
