# Changelog

Newest first, one section per day (`## YYYY-MM-DD`), and within a day one line per
user-visible change grouped Added / Changed / Removed / Fixed in that order. Write
the line under today's date as part of the change, creating the heading if today
has none yet ([0024](decisions/0024-changelog-is-dated-by-day.md)).

## 2026-08-01

### Added

- Tool modals can hold a `kind: 'choice'` field, rendered by a new `SegmentedControl` and gating steps through `whenFieldIs` — so one card can serve two audiences without a tab component and without a second card repeating half of it. It is native radios styled as a segment rather than buttons, which is why arrow keys, tab order and the announced group name need no code. Steps also gained `tooltip` (the caveat only some readers need, behind an info icon, instead of a longer note), `link` (for a step a terminal can't carry out, like an admin console page), and modals gained `requireFields`, which withholds every step — and the mode picker — until the named field is filled: a command built around an unfilled token looks runnable and isn't, prose carrying the same token reads as broken while numbering itself from 1 as though the steps above it didn't exist, and choosing a path is pointless while everything behind it is withheld. Text fields render before choice fields for the same reason: a field the modal is gated on has to be answerable before anything it gates appears. The modal's intro is what explains the card in the meantime ([0034](decisions/0034-modal-modes-are-a-choice-field.md)).

- `.claude/hooks/guard.mjs` rejects, at Stop, the comment tells `code-style.md` names outright — an emoji, a section banner, a `Note:` prefix — in comment lines the working tree added, reading both `git diff HEAD` and the untracked files a diff can't see. It deliberately stops there: the comments that prompted it were well-formed English that merely restated a decision file, and no regex sees that, so the rule file keeps the judgement half and the script says so ([0035](decisions/0035-comment-guard-enforces-only-the-mechanical-half.md)). The team setup prompt generates the same check, with the two traps that surfaced here — anchor the `Note:` pattern or an ordinary sentence containing "note:" trips it, and read untracked files whole or a new file is the one place the check is blind.
- The footer carries an attribution — "© &lt;current year&gt; Ali Hussein", the name linking to the GitHub account this repo lives under — opposite the existing note about where progress is saved. The year is read at load rather than written into the source, so it can't go stale in January. The two sit on one row from `sm` up and stack below it. The row's right padding is written per-side rather than as `px-*`, because `ScrollTop` is fixed over the last 60px of the viewport and the widest breakpoint's shorthand would otherwise reset the clearance.

### Changed

- `scan.ps1` ends on `Press Enter to close...` and then exits the console. The results are the point of the run, so the window neither vanishes before they're read — the double-clicked `.ps1` case — nor is left sitting there afterwards. `exit` closes the session itself rather than only ending the script, and the prompt is a separate `Write-Host -NoNewline` because `Read-Host` appends `: ` to any prompt it is handed. Unconditional rather than guarded on `$MyInvocation.MyCommand.Path`, which would never fire for the paste the modal actually hands out. The Unix script is unchanged — a terminal running `scan.sh` stays open by itself.
- herdr's card says what it is — "A terminal multiplexer for AI coding agents" — rather than what you do with it. "(tmux-style)" was carrying that meaning as an aside, and tmux is the multiplexer the phrase was pointing at.
- The status line moved out of Project Setup and into the Claude Code card's setup modal, where the three options now follow signing in. It was the only card in that section that configured Claude Code rather than acting on a repo, which is why the section's description had to mention both; it now describes only what's left. The move deliberately costs nothing elsewhere: the AI setup prompt skips the Claude Code card wholesale, so a nice-to-have stays out of the walk-away run, and there's no new tickable item or scan entry. Its docs link and its caveat about rate limits survive as a step link and tooltip.
- The "Team setup prompt" card states `Prerequisite: Repo cloned`, which the neighbouring "Run-the-app docs" card already did for the same requirement.
- The "Team plugin" card is two modes, Create and Install, instead of one list mixing them. It now describes a company marketplace — `{company}-claude` holding a baseline plugin named `{company}` plus a plugin per stack, `{company}-rn-mobile` as the worked example — rather than a single plugin whose name matched its marketplace. Naming follows the ecosystem rather than an invention: nothing in the official catalog calls a baseline plugin "core", the pattern is flagship = bare name and variants = suffix. Install carries an HTTPS/SSH toggle on the one command that differs, defaulting to HTTPS because Git ships a credential manager on both Windows and macOS while SSH needs a key already loaded in `ssh-agent`. Create ends with an optional step for Team and Enterprise plans: an admin adds the repo as `owner/repo` under Organization settings → Plugins and picks how it lands: install by default and every developer has it without running the Install commands, required and they can't uninstall it either, available and they pick it out of the Browse plugins modal — the distinction that decides whether the Install tab is needed at all. The step links straight to that settings page, and its prerequisites sit in the tooltip: the Claude GitHub App on the repo, admin access to it, and Cowork and Skills enabled for the org. Tooltips hold what most readers don't need: that a plugin repo is cloned in plaintext to every machine and is no place for a token, and that `claude plugin details` prints what the thing costs in tokens before you ship it to everyone ([0034](decisions/0034-modal-modes-are-a-choice-field.md)).
- `PLUGIN_FILL_PROMPT` becomes `PLUGIN_BUILD_PROMPT`: it writes the marketplace and the baseline plugin into an empty repo rather than filling a folder left behind by `claude plugin init`, which scaffolds one plugin at `~/.claude/skills/<name>/` — the wrong shape and the wrong place for a marketplace. What it generates is five hooks and nothing else. No skills and no agents in a baseline, and specifically no text loaded on every message, because the per-repo setup card already writes prose rules into `.claude/rules/` and must keep doing so for the repos that never install the plugin. A plugin and a repo then produce different kinds of thing and cannot duplicate each other. The comment rule still travels with the plugin, as a hook that injects it at the moment a code file is edited and greps the host repo's own rules first to stay quiet where they already cover it ([0034](decisions/0034-modal-modes-are-a-choice-field.md)).

### Removed

- The hook that asked before an existing `docs/decisions/` file was edited, and with it the only `PreToolUse` entry in `.claude/settings.json`. It fired on every revision of a decision written in the same session as the work it records, which is the normal case rather than the contract violation it was watching for ([0030](decisions/0030-conventions-as-rules-and-hooks.md) introduced it). Decisions are still superseded rather than edited — that rule stays in `CLAUDE.md`, unenforced, like the rest of the judgement-shaped ones.

### Fixed

- `.claude/hooks/guard.mjs` runs at all. It imported `fs.globSync`, which arrived in Node 22, so on Node 20 the import threw before any statement executed; the process exited 1, Claude Code treated that as a hook error, and the session ended — meaning the Stop check on the changelog contract had never once fired here. File lists now come from `git ls-files`, which has no version floor ([0035](decisions/0035-comment-guard-enforces-only-the-mechanical-half.md)).
- Typing in a tool modal's field no longer throws focus back to the dialog after the first character. `Modal` set the initial focus inside the same effect as the Escape listener, keyed on `onClose` — which every caller passes as an inline arrow, so the effect re-ran on every render and re-focused the panel mid-keystroke. The initial focus is now its own mount-only effect. Visible on any card with a field, and worst on the team plugin card, where the first character also changes what's rendered below.
- A step's `note` renders `{field}` tokens like its command does, instead of printing the brace form. The team plugin card's install line names your own stack plugin (`{company}-rn-mobile@{company}-claude`), which was the first note that needed it.

### Changed

- herdr's Homebrew command on macOS is labelled "Copy brew install" rather than a bare "Copy". The Claude Code card above it already labels its npm route this way.
- `new-feature` and `fix-bug` are skills (`.claude/skills/<name>/SKILL.md`) rather than files under `.claude/commands/`. Custom commands were merged into skills, so both shapes produce the same `/name` — but a skill also loads when Claude judges it relevant, where a command fires only when someone types it. "Reproduce before you fix, then take the smallest diff" is worth having on a session that opens with "the rail rows don't do anything" and no slash command, and as a command it was opt-in exactly where it mattered. Bodies unchanged, `argument-hint` and `$ARGUMENTS` behave the same, and the descriptions gained the "Use for …" trigger clause the other three skills already had. The team setup prompt stops generating a `commands/` directory for every repo it touches ([0032](decisions/0032-workflow-commands-become-skills.md)).
- The detect scan's pairing session outlives its modal. Copy the script, close the modal, run it whenever — the page is still listening, and when the report lands it reopens the modal on the same result panel as before: what was ticked, what was cleared, Undo, Scan again. Closing used to abort the poll and reopening minted a new code, which quietly killed a script already sitting in your clipboard. The session and the pre-scan snapshot Undo replays now live in `App` (the snapshot had to move too: with the report outliving the modal but the snapshot dying with it, a reopen re-applied the report and snapshotted the post-scan state as the one to restore, turning Undo into a no-op that eats hand-entered ticks), and `detect.ts` owns what a result does to the checklist so the relay path and the manual paste can't drift. Nothing polls until you open the modal once. If the AI setup or a tool modal has the screen when a report arrives, nothing pops — the ticks land behind it, and since the AI setup reads the same checklist, its tool list and its prompt shrink while you watch ([0033](decisions/0033-detect-session-lives-in-app-and-codes-dont-expire.md)).
- Pairing codes don't expire any more — no "Code expired", no "New code" button, nothing for you to redo because the page stopped listening. There was never a relay session to expire: KV holds nothing until the script posts a report, and the 10-minute TTL starts there ([0003](decisions/0003-single-use-pairing-codes-with-tombstone.md)), so the page's own countdown was a mirror of that number whose only effect was to stop polling before a distracted user got round to running the script — the report then landed under a code nobody was reading and died ten minutes later, silently. A code now lives as long as the tab, and the poll backs itself off instead: every 2s for the first two minutes, then 10s, then 60s, so a tab left open all day costs a few hundred relay reads rather than ~1,800 an hour. A scan run late shows up within a minute instead of instantly; run in the first two minutes, which is the normal case, it still lands in one tick. The generated script's own header and the README say the same thing now — the code works once, and the ten minutes belongs to the report it posts, not to the code ([0033](decisions/0033-detect-session-lives-in-app-and-codes-dont-expire.md)).
- The statusline card's note is a sentence instead of a paragraph. It still names the two things no profile can show — permission mode and pre-first-response rate limits — but at 190 characters rather than 450, where the longest note on any other card is 198.
- The AI setup modal's `--dangerously-skip-permissions` explainer is two lines instead of five, with the alternative — approve each step yourself, which means not walking away — behind an info tooltip. The warning that it runs the whole list without checking with you stays on the page, since a hover tooltip doesn't exist on touch. It also stopped pointing at "the second line above", which was wrong whenever Claude Code is already ticked off on the page and the launch command is line 1 ([0031](decisions/0031-remote-control-is-an-optional-line-in-the-ai-setup.md)).

### Fixed

- Restoring a herdr workspace brought back every tab and its folder and not one conversation — each pane a bare shell, each chat to be found again through `/resume`. The card had promised the opposite, that herdr "reopens the workspaces it saved itself": true of tabs and folders, but an agent pane resumes only where an official integration has reported that pane's native session id, and the card never installed one. It ships `herdr integration install claude` now — one line with no platform variant, and the first step on that card to count as machine setup rather than reference, so the AI setup runs it instead of leaving it for the reader to notice. `session.resume_agents_on_restore` already defaults to `true`, so writing it into `config.toml` — the first fix attempted, on a real machine — changed nothing; the integration was the only missing piece, and also the only one needing no per-OS path ([0029](decisions/0029-herdr-persistence-needs-the-integration-not-config.md)).
- The AI setup would have skipped the JDK on a machine already carrying a newer Java. Rule 1 told the agent to skip anything "present and healthy", and JDK 20 answers `java -version` perfectly well, so React Native's hard requirement on 17 went uninstalled and Gradle failed later on the mismatch the card itself warns about — the same version-blind check [0022](decisions/0022-jdk-detected-by-pinned-paths-not-javac.md) fixed in the detect scan, left standing in the other derived surface. A pinned version now means that version: the agent checks it, installs the pinned one regardless of what else is present (parallel JDKs coexist safely), and resolves it without asking. The final verification checks `JAVA_HOME` resolves to the pinned JDK rather than to any JDK, since Gradle reads `JAVA_HOME` and not PATH. Repointing `JAVA_HOME` is the one change with a blast radius beyond this setup, so its old and new values go in the closing summary — a line in a report, not a mid-run question ([0023](decisions/0023-ai-setup-front-loads-asks-not-subagents.md)).
- Clicking the category rail's last row scrolled to the bottom and highlighted MCP Servers instead. Two things were wrong: the click was never recorded at all — the highlight came only from the scroll observer — and the sections at the end of the page can never win that observer's band, which stops at 35% of the viewport height while their headings sit below it at full scroll with no more page to scroll. So scrolling to the bottom by hand was wrong too, with no clicking involved. A clicked row is now held until you scroll for yourself, and the end of the page names the last section directly. The chips strip below `xl` marks the chip you tapped — still no scroll-spy there, which would drag the strip out from under your thumb ([0026](decisions/0026-rail-highlight-follows-clicks-not-only-scroll.md)).
- Detect scan ticked the JDK card green for any Java at all: it checked `javac` on PATH beside its version-pinned paths, and checks are any-of, so JDK 21 with no 17 read as installed — telling you setup was done right before Gradle failed on the mismatch the card itself warns about. It now rests on version-pinned paths only, widened to Zulu/Temurin/Microsoft and the arm64 Linux layout ([0022](decisions/0022-jdk-detected-by-pinned-paths-not-javac.md)).
- Twelve cards showed no version badge — Cursor, Android Studio, Docker Desktop, pgAdmin, Postman, Termius, Zoho Cliq, Slack, the JDK, and the three plugin cards. Cursor's own version endpoint sends no CORS header and it publishes no GitHub releases, so the installer-only apps now read the Homebrew cask API (same cask they install from, `Access-Control-Allow-Origin: *`, no rate limit); the plugin cards had GitHub releases all along. Xcode, Cisco, Teams desktop and the remote MCP servers stay bare on purpose ([0021](decisions/0021-version-badges-via-homebrew-cask-api.md)).
- Version badges can be per-platform, for the two cards where one number can't be right for everyone: Teams ships a different build per OS (mac shows the cask number, Windows/Linux stay bare) and the Homebrew / winget card fronts a different package manager per OS (mac and Linux show Homebrew's) ([0021](decisions/0021-version-badges-via-homebrew-cask-api.md)).

- Detect scan reported a freshly installed Claude Code plugin as missing: it searched `~/.claude.json`, which only records a plugin once it has been used, rather than `~/.claude/settings.json`, which records it at install. Superpowers, UI/UX Pro Max and Slack passed only on usage history; installing Ponytail and scanning is what exposed it ([0012](decisions/0012-plugins-detected-via-claude-settings-json.md)).
- Typed modal values reached the shell unescaped — double-quoted for git identity, the SSH key comment and the Zoho MCP URL (where `"`, `$` and a backtick are all still live), and bare for the fnm/pnpm/yarn version fields. All seven moved to single-quoted literals behind the same `shellQuoted` escape the herdr launcher uses, so a name like O'Brien fills correctly instead of splitting the command.
- The `--dangerously-skip-permissions` callout in the AI setup modal was 512px wide inside a ~970px dialog, so the page's one safety warning was also its narrowest box. `max-w-lg` was capping the bordered container instead of the prose inside it; the box now fills the modal like its neighbours and the text keeps its readable line length, the same shape the "Included tools" panel twelve lines below already used.
- "View setup" was styled solid accent on cards that had no install command and outlined on cards that did, so the emptiest cards (Superpowers, Ponytail, the plugin-style MCP servers) shouted loudest while a card full of commands whispered. It's always the quiet outlined button now; the solid accent is reserved for the action that actually installs the tool.
- Tool modals listed the prerequisite below the fill-in fields, so you only learned what you needed after filling the form in — it now sits directly under the intro, above the fields.
- herdr launcher dropped its "Start folder" field: `herdr` takes no path argument and restores its own saved workspaces, so the field set a working directory that only ever affected a first-ever launch while reading as though it chose the project.
- herdr launcher didn't check the install folder — a typo silently created a directory tree and hid the launcher in it — and `~`, which the placeholder suggests, was expanded on Unix but not on Windows. It now expands `~` everywhere and refuses with the offending path named.
- The launcher's failure paths called `exit`, which closed the whole terminal — it runs inside the user's session via `&([scriptblock]::Create(…))`, not a child process — so the message vanished with the window. They `return` now.
- A failed icon fetch deleted the installed icon before validating the replacement, leaving a working launcher iconless; the download is checked aside and only swapped in once it passes.
- The herdr launcher aborted before writing anything under PowerShell 7: its icon check read magic bytes with `Get-Content -Encoding Byte`, a 5.1-only switch that throws in 7, and `$ErrorActionPreference = 'Stop'` turned that into a dead stop on the default no-custom-icon path. It reads via `[IO.File]::ReadAllBytes` now, which both editions accept.
- Smaller launcher and modal fixes: the icon one-liners deleted the temp icon they wrote; `--dest`/`--icon-file`/`--icon-url` now name the option when handed no value instead of failing on a bare `shift`; the icon drop zone stopped flickering its border when the cursor crossed the preview mid-drag.
- `pnpm build` never typechecked the relay: `functions/` was in no tsconfig, so a type error there deployed unnoticed. `tsconfig.node.json` now includes it (verified by injecting an error and watching the build fail). `scripts/` stays out — it runs under `tsx`, and bending a working dev script to `nodenext` resolution rules buys nothing.
